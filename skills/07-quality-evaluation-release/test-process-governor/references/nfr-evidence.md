# NFR 测试证据与流程门禁

本文件只治理测试阶段证据。每项 NFR 记录 `source_ref`、`approval_status` 和 `scope`；范围与判据、工具环境、生产动作分别交给对应技能。

## 阶段链路

| 阶段 | 必需输入与动作 | 输出/门禁 |
| --- | --- | --- |
| 需求评审 | 来源、对象、风险、批准角色；检查可测性 | 清单、未知项；高风险无口径时未就绪 |
| 测试设计 | 判据、负载/故障；建立覆盖和环境计划 | 用例、追踪、估算、排除；缺场景则退回 |
| 提测准入 | build、隔离环境、配置和可观测；完成试运行 | 基线快照；环境不可信或触达生产则不准入 |
| 执行 | 冻结版本和计划；保留原始数据与偏差 | 结果、Trace、缺陷；证据失真则暂停/重跑 |
| 准出 | 对照批准判据，核对缺陷和复测 | 结论矩阵；高风险失败或证据不足不得通过 |
| 发布交接 | 汇总监控、阈值和恢复关注点 | 证据包和遗留风险；发布技能形成最终动作 |

## 就绪度与执行证据

提测前至少确认：来源与批准、SLI 公式、目标/窗口、负载/故障、环境差异、工具校准、生产隔离、数据安全、停止/恢复、排除项和责任人。

每次执行至少记录：

- build、配置、拓扑、区域、依赖、工具/脚本/数据版本和时间。
- 预热、并发/到达率、时长、数据分布、故障和恢复动作。
- 原始样本、公式、百分位/窗口、错误分类、资源和队列。
- 指标、日志、Trace、告警和业务结果的关联 ID。
- 计划偏差、工具限制、丢样、重试、无效运行和人工干预。
- 目标、实际、结论、缺陷、复测、风险、责任人和证据位置。

只有截图或聚合数字不足以证明复杂 NFR；保留原始数据或可重复查询、脚本和版本快照。

## 问题分域

| 类型 | 处理 |
| --- | --- |
| 产品/实现缺陷 | 按缺陷流程分级、修复、复测和影响面回归 |
| 需求/标准缺口 | 指定批准人，形成门禁前保持待补证据 |
| 环境/工具限制 | 暂停可信度判定，修复或披露后重跑 |
| 容量/架构风险 | 登记风险与行动，不伪造成实现缺陷 |
| 外部依赖异常 | 保留失败并验证己方隔离、降级和恢复 |

## 准出

`PASS` 要求全部必测项有批准判据、可信证据并达标；`PASS_WITH_ACCEPTED_RISK` 只容纳获批非阻塞项；硬失败为 `FAIL`；结果不可信为 `PAUSED`；关键信息不足为 `BLOCKED`。

安全、隐私、越权、误计费、核心数据、恢复失败和 Agent 高风险有效失败不能被平均值抵消。测试准出不等于长期生产 SLO 已完成。

发布交接包含 NFR 结论矩阵、必须监控的 SLI、灰度/停止条件、哨兵验证、环境差异和遗留风险；不得声称生产动作已经执行。
