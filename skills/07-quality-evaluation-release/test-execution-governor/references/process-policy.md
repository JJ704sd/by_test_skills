# 测试生命周期门禁规则

项目标准优先，但必须记录 `source_ref`、`approval_status` 和 `scope`。不同口径不能只比较数字大小；无法裁定时保持 `BLOCKED`。

## 阶段链路

| 阶段 | 必做动作 | 输出/证据 |
| --- | --- | --- |
| 需求分析 | 评审业务、范围、验收、依赖、风险和可测性 | 纪要、未知项、初步范围 |
| 测试设计 | 设计场景、数据和环境；完成适用评审 | 用例、范围、准备清单 |
| 开发与提测 | 开发自测并提交可测版本和影响说明 | build、自测与变更证据 |
| 版本测试 | 准入、冒烟、系统测试、缺陷、回归和验收 | 执行、缺陷、回归、验收与报告 |
| 发布交接 | 风险评审和发布证据交接 | 测试准出、遗留风险和线上验证项 |

失败必须回流：评审、准入、冒烟或验收失败时返回对应修复节点，重新提交后重跑受影响门禁。

## 流程深度

| 类型 | 可压缩 | 不可省略 |
| --- | --- | --- |
| 常规迭代 | 无 | 阶段证据、评审、测试和交接 |
| 紧急修复 | 评审和范围可按批准最小化 | 修复点、核心冒烟、影响说明、回滚、线上验证和复盘 |
| 大版本/重构 | 不压缩，只加固 | 全量回归、核心加固、适用专项和预发布验证 |

## 提测准入

全部满足后进入正式测试：需求和重大歧义有结论；开发自测无阻塞；环境、数据、账号、权限和依赖就绪；版本可部署且核心服务可用；范围、用例、优先级和计划已确认。

## 暂停条件

命中任一项即暂停并记录触发证据、版本、影响、责任人、恢复条件和重跑范围：

1. 冒烟失败率超过已批准阈值，或核心流程存在 P0。
2. 环境或服务不稳定，使结果不可信。
3. 出现无规避方案的 P0。
4. 版本频繁且未通知地变化，导致测试不可控。

## 门禁状态

| 人类状态 | 机器状态 | 判定 |
| --- | --- | --- |
| 通过 | PASS | 强制条件有证据且无不可接受风险 |
| 有条件通过 | PASS_WITH_ACCEPTED_RISK | 仅有已批准非阻塞项，含补偿、责任人和期限 |
| 不通过 | FAIL | 硬门禁失败或有不得遗留风险 |
| 暂停 | PAUSED | 继续执行不可信或会扩大风险 |
| 待补证据 | BLOCKED | 信息不足以判定，列出最小补充材料 |

已知硬失败且环境可信时优先 `FAIL`；P0/P1 未修复并回归通过时不得有条件通过。

## 准出、执行完成与关闭

测试准出至少要求：计划内用例完成；P0/P1 修复并回归；修复点和影响面无新增阻塞；产品验收完成；报告已评审；遗留风险获批并有责任人和计划。

“执行完成”只表示计划测试和回归已形成证据，不等于准出。准出、报告、遗留跟踪和发布交接归档后，生命周期才可关闭。

若组织规定计划上线前冻结常规测试，记录具体截止时间、时区、例外流程和批准人。Hotfix、回滚恢复冒烟和发布后只读验证必须作为独立流程记录，不能伪装成常规测试延续。

## 缺陷

| 等级 | 定义 | 门禁 |
| --- | --- | --- |
| P0 | 核心不可用、严重安全或数据风险 | 立即升级，本轮修复，不得发布 |
| P1 | 主要功能异常且无合理规避 | 本轮修复并回归，不得遗留 |
| P2 | 非核心异常且有规避 | 跟踪闭环，可经批准延期 |
| P3 | 不影响使用的轻微问题 | 进入优化队列 |
| P4 | 建议类体验优化 | 按产品优先级处理 |

缺陷按提交、确认、修复、待验证、验证/重开、关闭流转；挂起必须有原因、风险、责任人和目标版本。用例 CP0/CP1 与缺陷 P0/P1 不得混用。
