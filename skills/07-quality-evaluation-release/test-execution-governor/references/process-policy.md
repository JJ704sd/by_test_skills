# 确定性测试生命周期策略

项目规则优先；每项门禁记录 `source_ref`、`approval_status`、`scope` 和 threshold/profile 引用。口径冲突无法裁定时保持 `BLOCKED`。

| 决策点 | 必需证据 | 失败动作 |
| --- | --- | --- |
| `ENTRY_GATE` | build、自测、范围、用例、环境、数据、账号、权限、依赖和观测就绪 | 不准入并列最小整改 |
| `CONTINUE_OR_PAUSE` | 冒烟、环境可信度、版本稳定、缺陷与偏差 | 不可信则 `PAUSED`；可信硬失败则 `FAIL` |
| `EXIT_GATE` | 计划证据、修复点与影响面回归、P0/P1、验收、NFR、报告和遗留风险 | 硬失败 `FAIL`；缺证 `BLOCKED` |
| `EXECUTION_COMPLETION` | 计划执行和回归形成证据 | 只更新执行状态，不推导准出 |
| `LIFECYCLE_CLOSURE` | 准出、报告、遗留跟踪和发布交接已归档 | 保持开放并列缺口 |

测试流程可按经批准风险压缩，但修复点、核心哨兵、影响说明、恢复/回滚关注点、证据和复盘不能省略。评审、准入、冒烟或验收失败时返回对应节点，重新提交后重跑受影响门禁。

## 状态

| machine_status | 语义 |
| --- | --- |
| `PASS` | 所有适用硬条件有可信证据且满足批准判据 |
| `PASS_WITH_ACCEPTED_RISK` | 仅有经批准的非阻塞风险，含补偿、责任人和期限 |
| `FAIL` | 可信硬门禁失败或有不得遗留风险 |
| `PAUSED` | 继续执行不可信或会扩大风险 |
| `BLOCKED` | 信息不足以判定，列出最小补充证据 |

NFR 执行必须冻结 build、拓扑、工具/脚本/数据、公式、负载/故障、窗口和批准 profile，保留原始样本、错误分类、资源、日志/Trace、偏差、人工干预和恢复证据。安全、隐私、越权、误计费、核心数据、恢复或高风险有效失败不能被平均值抵消。

P0 表示核心不可用或严重安全/数据风险；P1 表示主要功能异常且无可接受规避。两者未修复并完成影响面回归时不得准出。其他缺陷按项目严重度策略处理；用例优先级不能与缺陷严重度混写。
