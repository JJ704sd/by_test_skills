# 测试工具能力目录

从能力契约出发，不把仓库中的产品名当作当前标准。候选产品、版本、许可、维护状态和团队可用性必须在决策时核验并记录来源与日期。

## 能力矩阵

| 场景 | 必需能力 | 关键限制 | 必留证据 |
| --- | --- | --- | --- |
| 用例/缺陷管理 | 唯一权威源、版本、追踪、权限和审计 | 不并行维护多个“最新版” | 需求-用例-缺陷-版本关系 |
| 接口调试 | 环境隔离、变量、鉴权、Schema 和可导出集合 | 不硬编码域名、Token 或业务 Secret | 请求、断言、环境和集合版本 |
| 接口自动化 | fixture、参数化、断言、报告和 CI | 重试不掩盖首次失败 | 脚本、数据、原始失败和报告 |
| UI 自动化 | 稳定定位、Trace、并行和跨平台 | 只覆盖稳定高价值链路 | 代码、浏览器矩阵、截图/Trace |
| 性能/容量 | 负载模型、百分位、错误分类和资源关联 | 负载器可能成为瓶颈；禁止生产发压 | 脚本、配置、原始样本和曲线 |
| 安全 | 授权范围、规则版本、人工复核和脱敏报告 | 禁止扫描或渗透生产 | 范围、规则、结果、误报复核 |
| 日志/监控 | 查询、Trace ID、时间过滤、告警与脱敏 | 高基数、丢样和隐私风险 | 查询、仪表盘、Trace 和告警送达 |
| Prompt/Trace | Prompt、模型、参数、工具和上下文版本 | 不直接覆盖生产配置 | 版本清单、请求 ID 和回放证据 |
| Agent 评测 | 版本化测试集、批量采样、规则/Schema/人工判定 | LLM Judge 不能独占高风险判定 | 逐次输出、Judge 路径、基线和报告 |

## 场景约束

- 接口断言至少覆盖状态、关键字段、业务错误、鉴权、边界、幂等、超时和依赖失败。
- 自动化优先稳定、高频、高价值且 Oracle 清晰的行为；录制脚本整理并补业务断言后才可入库。
- 性能执行前冻结并发/到达率、Ramp-up、时长、数据、停止条件和观测指标。
- 安全检查覆盖认证、授权、输入攻击面、敏感数据和日志脱敏；高风险模块保留经授权人工验证。
- Agent 固化模型、参数、Prompt、规则、工具、知识库、Schema、数据集和评测脚本版本。
- 分开记录技术失败和语义失败；保留请求 ID、Trace、耗时、重试和原始输出。

## 判定能力验收

候选工具必须准确表达已批准的判定：

| 判定类型 | 能力要求 |
| --- | --- |
| 计费/计算 | 精确值或批准容差，保存输入、公式和逐次结果 |
| 实体/单位 | 字段比较、归一化规则、分子/分母和失败样本 |
| 推荐/语义 | 批准量表或候选范围、人工复核和一致性记录 |
| 鲁棒/安全 | 固定数据集、逐次高风险结果和可定位失败 |
| 输出格式 | 版本化 Schema/规则、字段差异和原始输出 |

若精度、数据类型、聚合或原始证据不满足当前阈值契约，应限定采用或不采用，不得修改产品阈值迁就工具。
