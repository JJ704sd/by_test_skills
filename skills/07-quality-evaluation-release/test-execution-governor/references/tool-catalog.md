# 测试执行能力目录

从能力契约出发；产品、版本、许可、维护和团队可用性在决策时现场核验并记录来源与日期。

| 场景 | 必需能力 | 关键限制 | 必留证据 |
| --- | --- | --- | --- |
| 用例/缺陷管理 | 权威源、版本、追踪、权限和审计 | 不并行维护多个最新版 | 需求-用例-缺陷-版本关系 |
| API/UI 自动化 | 环境隔离、fixture、断言、Trace、报告和 CI | 重试不掩盖首次失败；只固化稳定链路 | 代码、数据、配置、原始失败和报告 |
| 性能/容量 | 负载模型、百分位、错误分类和资源关联 | 负载器可能饱和；禁止生产发压 | 脚本、配置、原始样本和曲线 |
| 安全/隐私 | 授权范围、规则版本、人工复核和脱敏 | 禁止扫描或渗透生产 | 范围、规则、结果、复核和清理 |
| 兼容/数据 | 平台、协议、Schema、对账和回放 | 组合爆炸与非幂等写入 | 批准矩阵、快照、事件和校验 |
| 可观测 | 指标、日志、Trace、告警和关联 ID | 丢样、时钟、高基数和隐私 | 查询、仪表盘、Trace 和告警送达 |
| Agent runner/Judge | 清单、批量采样、规则/Schema/人工判定 | LLM Judge 不独占高风险判定 | 逐次输出、Judge 路径、基线和报告 |

候选必须准确表达批准的 Oracle、公式、单位、threshold/profile 和原始证据。若精度、聚合、数据类型或安全不满足契约，只能限定采用、不采用或待评审，不能修改产品判据迁就工具。

性能、可靠、恢复或 Agent NFR 还要支持负载/故障、停止/恢复、组件拆分、技术/语义失败分域和版本关联。工具无法判定业务正确性时配合权威 Oracle 或人工复核，不能以请求成功代替质量通过。
