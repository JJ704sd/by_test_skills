# NFR 工具与环境治理

NFR 选型从指标、负载/故障模型、环境和证据出发。每项要求记录 `source_ref`、`approval_status` 和 `scope`；具体产品与版本必须现场核验。

## 能力契约

先回答：

- 产生什么协议、负载、数据分布、并发/到达率和时长？
- 控制哪些依赖、故障、延迟、错误、Schema 或区域状态？
- 采集哪些 SLI、原始样本、资源、日志、Trace 和业务结果？
- 如何关联版本、配置、请求、区域、模型和工具？
- 如何在 CI、定时任务或隔离演练中复现？
- 如何停止、恢复、清理数据并校准工具自身误差？

工具不能判定业务正确性时，配合权威 Oracle、契约断言或人工复核，不能用“请求成功”替代质量通过。

## NFR 能力矩阵

| 域 | 必需能力 | 关键风险 | 必留证据 |
| --- | --- | --- | --- |
| 性能/容量 | 负载模型、分布式发压、百分位、错误和资源关联 | 负载器饱和、网络瓶颈、重试放大 | 脚本/数据/配置、样本和资源曲线 |
| 可靠性/长稳 | 长运行、原始失败、断点/恢复和趋势 | 重试、轮转或采样掩盖失败 | 失败、重试计数和时间线 |
| 韧性/恢复 | 隔离故障、停止、恢复和回切 | 故障失控、环境污染、回切失败 | 注入计划、审批、动作和 RTO/RPO |
| 安全/隐私 | 授权、攻击面、脱敏和审计 | 误伤、敏感留存、误报/漏报 | 规则、范围、复核和清理 |
| 兼容/数据 | 平台/协议/Schema 矩阵、对账、回放 | 组合爆炸、非幂等写入 | 矩阵、快照、事件序列和校验 |
| 可观测 | 指标、日志、Trace、告警和关联 ID | 丢样、时钟、高基数、隐私 | 查询、告警送达和 Trace 样本 |
| Agent NFR | 批量/并发、组件耗时、Token、回放和故障 stub | 限流、缓存、非确定性和敏感输出 | 清单、逐次运行、技术/语义结果和用量 |
| 成本效率 | 按版本/场景/成功结果归集用量 | 以降质换成本、账单延迟 | 来源、分摊公式、质量并行指标和基线 |

## 环境与安全

- 禁止在生产执行压测、容量摸底、安全扫描、渗透、破坏性故障注入、删除或修改。
- 脚本不得默认或回退指向生产；环境名不等于真实隔离。
- 仓库、脚本、日志、Trace、报告和测试集不得保存明文 Secret 或未脱敏隐私。
- 隔离环境仍需最小权限、目标资源、窗口、值守、停止/恢复、清理和审计。
- 生产只允许项目制度批准的只读遥测和非破坏性采样；不能替代隔离测试。

## 可信度与试用

低负载校准请求量、响应和时钟；监控负载器、网络和采集端；保存首次失败与重试；记录预热、缓存、连接、限流和聚合配置。结果异常时先验证工具与环境可信度。

版本化脚本、非敏感配置、数据/Schema、负载/故障、Oracle、查询、报告和环境清单。失败必须能追踪到请求、工具日志、服务日志/Trace、版本和配置。

新工具在隔离、非核心范围验证能力、计数误差、失败分类、追踪、CI 稳定性、安全、清理、许可和维护成本。目标未批准时只能限定采用或待评审。

决策记录至少包含选择结论、执行授权、能力映射、环境/数据/权限、校准结果、版本化资产、限制、维护人和退出条件。
