# 工具选型与治理规则

## 决策

1. 列出 `must_have`、偏好和安全否决项。
2. 检查团队标准的已验证版本；满足全部必需能力时优先复用。
3. 记录缺口，只比较许可、部署和维护均可行的候选；命中否决项即淘汰。
4. 在隔离、非核心范围验证能力、计数、失败分类、Trace、CI、安全、清理和成本。
5. 记录 `source_ref`、`approval_status`、`scope` 和 `facts_verified_at`；事实或范围变化时失效。

安全否决不能被总分抵消。没有合格候选时输出 `REVIEW_REQUIRED` 或不采用，不扩大短名单或降低已批准判据。

## 引入与退出

- 显式区分环境并失败关闭，配置缺失时不回退生产。
- 使用个人身份、最小权限和批准的 Secret 系统；报告与资产只保存脱敏值。
- 正式资产版本化，包含断言、配置隔离、Review、原始证据、CI 和维护人。
- 推广前明确迁移、培训、审计、升级和退出；替换前验证回退并归档旧资产。

选型、执行授权和实施进度分别记录。`execution_authorization=ALLOWED` 必须引用外部可核验证据；本技能不能把建议当成授权。使用 [选型模板](../assets/tool-selection-templates.md) 时清除占位符，未知项写 `UNKNOWN`；安全否决或环境不可信时授权为 `BLOCKED`。
