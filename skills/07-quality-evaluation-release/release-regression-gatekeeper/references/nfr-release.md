# NFR 发布证据与门禁

把 NFR 组织成发布证据链。每项规则记录 `source_ref`、`approval_status` 和 `scope`；本文件不创造项目阈值，仓库基线未获批准时只能支持 `REVIEW_REQUIRED` 或 `BLOCKED`。

## 发布前证据

每个适用 NFR 至少包含：

- 对象、SLI 公式、目标/窗口、门禁、批准状态和来源。
- build、环境差异、负载/故障、数据、工具和原始证据。
- 当前值、基线、阈值、趋势、样本、错误分类和结论。
- 缺陷、复测、遗留风险、补偿、责任人和期限。
- 生产查询、告警、拆分维度、值守和升级路径。
- 灰度哨兵、停止/回滚和恢复验证条件。

| 域 | 发布前关键证据 | 生产准备 |
| --- | --- | --- |
| 性能/容量 | 目标负载、百分位、错误、资源余量和环境差异 | 延迟、吞吐、错误、资源/队列告警 |
| 可用/可靠 | SLI、依赖失败、长稳和基线 | 窗口、错误预算、依赖/区域拆分 |
| 韧性/恢复 | 降级、切换/回切、回滚演练和 RTO/RPO | 停止条件、稳定版本、负责人和验证 |
| 安全/隐私 | 权限、拒绝、脱敏和审计 | 安全硬条件、告警和值守 |
| 兼容/数据 | 客户端/Schema、迁移、回放和对账 | 版本拆分、数据校验和回滚兼容 |
| 可观测 | 指标、日志、Trace、告警演练 | 查询、送达和 Runbook |
| Agent NFR | 离线门禁、组件延迟、工具、降级、质量和成本 | 任务/工具/Schema/安全/漂移信号 |

数据库或 Schema 变更不能假设代码回滚即可恢复数据。不可逆迁移必须有快照/备份、对账、兼容或批准的向前修复，并验证恢复。

## SLO 与发布阈值

区分长期 SLO、错误预算、灰度阶段门禁和硬回滚条件。长期 SLO 达标不能抵消本次硬事件；短期灰度正常也不能证明长期 SLO 完成。

只有项目标准明确规定错误预算公式、燃烧阈值和动作时，才直接触发停止/回滚；否则只作为 `WATCH` 或升级信号。规则冲突时先比较对象、公式、窗口和批准范围，不能只比较数字大小。

## 灰度判定

每阶段冻结版本、配置、流量/白名单、观察时长、指标、基线、阈值和操作人。推进前检查：

1. 核心哨兵、业务正确性和安全拒绝无失败。
2. 错误、延迟、吞吐、资源和依赖信号在批准范围。
3. Agent 按模型、工具、Schema、区域拆分后无硬失败。
4. 数据完整性、兼容性、隐私和审计无异常。
5. 告警、日志、Trace 可用，样本足以判定。
6. 无新增 P0/P1，上一阶段异常已闭环。
7. 适用责任人已完成阶段确认。

指标缺失、采集失真、版本漂移或阶段未确认时不得放量。总体平均不能掩盖核心分片或工具失效。

## 停止、恢复与关闭

命中批准的可用性、错误、延迟、数据、安全、恢复、Agent 或监控硬条件时：立即停止推进并保全证据；按批准方案恢复稳定版本/配置；验证核心链路、数据/Schema、权限、安全、关键 NFR 和告警；观察至稳定并记录实际恢复时间和数据恢复点。

回滚不安全或失败时保持停止并升级事故指挥。生产不得以验证 NFR 为由执行压测、安全扫描或破坏性故障注入。

发布关闭要求核心验证和阶段门禁通过、观察期稳定、无未处置 P0/P1、记录完整、遗留风险与长期观察已交接。长期窗口未结束时，只能写“当前发布观察通过，SLO 持续观察中”。

输出包含状态、当前阶段、来源/批准、NFR 当前值/基线/阈值、灰度样本、监控、回滚验证、动作、责任人和证据位置。
