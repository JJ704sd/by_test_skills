# 回归模型与门禁

项目策略优先；仓库中的层级、数量和时长是设计基线，只有记录来源、适用范围和批准后才成为门禁。

## 回归原则

1. 变更功能和逻辑 100% 回归。
2. 上下游、依赖接口、关联流程和历史高发点纳入影响回归。
3. 主流程、用例优先级 CP0/CP1（原规范称用例 P0/P1）和高可用链路纳入核心回归；缺陷严重度继续使用 P0/P1。
4. 选择最小有效范围，不盲目全量；排除项必须有依据、剩余风险和补偿。
5. 记录范围、用例版本、轮次、结果、缺陷和结论，保证可追溯。

## 分层回归

### Agent

| 层级 | 范围 | 适用 | 执行 |
| --- | --- | --- | --- |
| 冒烟 | 约 10-30 条核心意图、基本回答、工具调用、多轮关键信息 | 所有版本 | 自动化或手工 10-30 分钟 |
| 核心 | 直接变更、关联 CP0/CP1 用例、常见用户问题、输出 Schema | 日常、Hotfix | 自动化优先 + 人工抽检 |
| 全量 | 全部用例、工具、意图、边界、异常、长对话、模型/输入长度兼容 | 大版本/重构、长期未发布 | 自动化 + 人工并行；补充多轮对话压力 |

### Web/API

| 层级 | 范围 | 适用 | 执行 |
| --- | --- | --- | --- |
| 冒烟 | 首页、登录/退出、核心业务流程、关键 API | 所有版本 | 手工或自动化 10-30 分钟 |
| 核心 | 变更模块、CP0/CP1 用例、核心增删改查和依赖接口 | 日常、Hotfix | 自动化优先 + 手工抽检 |
| 全量 | 功能、兼容、边界、异常、多浏览器/设备及接口压力 | 大版本/重构、长期未发布 | 自动化 + 手工并行 |

## 版本矩阵

| 版本 | 发布窗口 | 回归范围 | 轮次 | 通过标准 |
| --- | --- | --- | --- | --- |
| 日常迭代 | 固定窗口 | 变更点 + 核心功能 + 受影响模块 | 至少 1 轮 | 核心用例 100%；缺陷 P0/P1 零遗留 |
| Hotfix | 随时评估 | 修复点 + 冒烟 + 最小影响范围 | 1 轮，可压缩时间 | 修复点通过；核心流程无阻塞；回滚就绪 |
| 大版本/重构 | 规划窗口 + 灰度期 | 全量回归 + 核心加固 + 兼容/性能/稳定性 + 预发布 | 至少 2 轮：修复后、上线前 | 执行率 100%；缺陷 P0/P1 零遗留；风险可接受 |

## 范围确定

依次检查需求/验收、代码与配置差异、Prompt/模型/工具/知识库、上下游接口和数据、历史缺陷、线上逃逸及高频用户路径。将用例标为 smoke/core/full，记录排除项和补偿措施。

## 回归准入

- 开发自测完成并提交版本与影响说明。
- 测试环境稳定，数据、账号和依赖就绪。
- 回归范围和用例已评审。
- 上一轮阻塞问题已有结论。

## 回归准出

- 本轮计划用例全部执行，记录完整。
- 本次修复缺陷 100% 验证，修复影响面已回归。
- 核心流程/用例 100% 通过，无新增或遗留的缺陷 P0/P1。
- 产品完成业务确认。
- 排除项和非阻塞遗留风险有批准、补偿、责任人和期限。

## 回归输出

- 回归范围清单与排除依据。
- 用例版本、执行轮次和结果。
- 缺陷分级、状态和统计。
- 回归结论与发布建议。
