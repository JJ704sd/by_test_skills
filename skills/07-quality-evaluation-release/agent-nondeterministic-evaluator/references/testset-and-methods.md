# Agent 测试集与方法

## 测试集来源

- 经脱敏的真实用户日志。
- 历史失败、线上缺陷、客服反馈和投诉。
- 业务规则边界、长尾和高风险场景。
- 人工构造的缺省、错别字、歧义、噪声、诱导、越狱和攻击输入。

禁止提交手机号、地址、Token、订单隐私或其他未脱敏敏感数据。保留来源类别和脱敏状态，不保留不必要的原始身份信息。

## 测试集分层

| 集合 | 用途 | 维护要求 |
| --- | --- | --- |
| 核心回归集 | 每版必跑的高频核心和高风险场景 | 冻结版本，长期维护 |
| 增量问题集 | 最新线上失败、变更相关问题 | 每个版本按实际失败补充 |
| 鲁棒性集 | 缺省、错别字、歧义、噪声、超长 | 验证正确处理或友好提示 |
| 对抗集 | 越狱、诱导、权限绕过、敏感请求 | 高风险运行全部通过 |
| 长尾集 | 低频但影响高的边界 | 弥补主集遗漏 |

每条用例至少包含：ID、输入、期望解析（如适用）、关键输出、约束、判定方法、标签、风险、来源、测试集版本和采样次数。

测试集规模由风险、场景多样性和批准计划决定；数量不足时披露覆盖缺口，不复制相似输入凑数。

把测试集、标注、评测脚本和报告纳入 Git 或等价版本平台。归档时同时记录 Agent、Prompt、模型参数、规则、工具定义、知识库和环境版本。

## 离线方法

- **实体/单位**：关键字段和归一化结果精确比对。
- **计算**：用确定性代码或规则引擎计算期望，100% 校验。
- **推荐/决策**：规则或候选范围校验，争议项人工复核。
- **格式**：Schema 和禁止项校验。
- **鲁棒性**：空值、错别字、乱码、歧义、噪声、超长和缺省输入。
- **多样性**：同一意图的数字/中文数字、单位、口语、紧凑格式和改写。
- **上下文漂移**：插入无关轮次后保留关键事实；覆盖纠正、撤销和冲突信息。
- **对抗性**：越狱、提示注入、权限绕过、敏感请求和工具滥用。
- **一致性**：同输入重复采样，比较关键字段而非表面措辞。
- **工具链**：工具选择、参数、结果使用、超时、空结果、重复调用、权限失败和回退。

## 专项频率

| 专项 | 最低频率/触发 |
| --- | --- |
| 多轮上下文保持 | 每个相关版本 |
| 长文本/超长上下文 | 上下文策略或相关能力变更 |
| 中英混合、方言、拼音 | 按用户分布和语言风险 |
| 时效性/有效期 | 涉及时效逻辑时执行 |

纯 UI 行为和无关闲聊不纳入非确定性核心门禁；按风险抽检即可。API 连通、服务可用和稳定复现的工具接口故障交给通用测试流程。

## 执行与归因

每次运行记录请求 ID、时间、候选/基线版本、模型参数、Prompt/工具/知识库版本、测试集/用例 ID、原始输入输出、Trace、错误、重试和耗时。

失败初步归因为：Prompt、模型、规则/代码、工具规划、工具接口、知识库、上下文、测试数据、标注、环境或评测脚本。归因是调查假设，不要在无证据时写成根因。

人工抽检按批准计划覆盖实体、推荐、上下文、幻觉和安全等语义维度；高风险失败全部复核，人工结果与自动指标分开记录。

## 低浪费执行顺序

1. 对清单、脱敏、阈值、Oracle、Schema、runner 和 Trace 做静态预检。
2. 选取覆盖 exact、schema、rule、semantic、tool/context 和 high-risk 的最小代表集做 dry-run。
3. dry-run 通过后，先运行变更相关集、增量问题集和高风险集，快速暴露明显退化。
4. 正式准出继续完成该版本要求的核心/全量集合；前一阶段失败不能用来跳过必须报告的门禁状态，但可 fail-fast 停止额外非必要调用。
5. 判定按 exact/schema、确定性规则、语义量表、人工复核逐层升级；保存 `judge_path`。
6. 用 `case_id + agent_manifest + dataset_version + judge_version` 形成缓存键，只缓存 Oracle/规范化/判定中间件，不缓存候选 Agent 的实际输出。
7. 失败按技术错误码、Schema 差异、规则 ID、工具/上下文路径和语义原因聚类；报告簇大小和代表样本，所有原始失败仍可追溯。

dry-run 不能改变正式样本计划。若要把 dry-run 计入正式结果，必须在运行前声明其与正式环境、版本、配置和采样完全一致，并在计划中明确纳入。
