# Agent 测试集与方法

## 分层与版本

| 集合 | 来源与用途 |
| --- | --- |
| 核心回归 | 高频核心、高风险和长期维护场景 |
| 增量问题 | 变更影响、历史失败、线上缺陷和反馈 |
| 鲁棒/长尾 | 缺省、噪声、歧义、超长和低频高影响边界 |
| 对抗 | 越狱、注入、权限绕过、敏感请求和工具滥用 |

数据必须最小化、脱敏并保留来源类别。每条用例记录稳定 ID、输入/上下文、期望、约束、Judge 路径、风险、来源、数据集版本和 sampling profile 引用。规模由风险、多样性和批准计划决定；不足时披露缺口，不复制相似输入凑数。

同时版本化 Agent、Prompt、模型参数、规则、工具定义、知识库、Schema、标注、评测脚本和环境。

## 判定方法

- 实体、单位、计算、格式和禁止项优先使用精确规则、Schema 或确定性代码。
- 推荐与开放语义使用批准量表或候选范围，并对争议与高风险项人工复核。
- 鲁棒性覆盖空值、错别字、乱码、噪声、超长和缺省；上下文覆盖纠正、撤销、冲突与无关轮次。
- 工具链覆盖选择、参数、结果使用、超时、空结果、重复调用、权限失败和安全回退。
- 一致性比较关键字段或业务结果，不比较表面措辞。

## 执行与归因

先静态预检清单、脱敏、profile、Oracle、Schema、runner 和 Trace，再以代表集 dry-run，之后执行变更相关、高风险和批准的完整计划。fail-fast 可以停止非必要调用，但不能省略门禁状态和证据。

每次运行记录请求、时间、候选/基线、数据/用例、配置、原始输入输出、Judge 路径、Trace、失败、重试和耗时。失败归因为待验证假设；按技术错误、Schema、规则、工具/上下文和语义原因聚类，所有原始失败仍可追溯。
