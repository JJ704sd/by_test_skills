# 在线质量信号与缺陷分域

`online_monitor` 只观察已获发布许可的阶段。在线 profile 必须记录流量/人群选择、数据最小化、有效样本定义、窗口、切片、指标公式、批准 threshold、缺失策略、停止信号、查询和证据；任何比例、样本或时长都不得从仓库默认推定。

参考基线与当前窗口要冻结 Agent、Prompt、模型、工具、知识库、Schema 和流量构成。分别报告技术成功、解析/任务成功、工具失败、反馈、用户修正、安全拒绝、延迟和漂移，并按业务、语言、工具、区域等风险切片。样本结构不可比时 `REVIEW_REQUIRED`，数据或观测不足时状态为 `BLOCKED` 且信号为空。

## 信号

- `OK`：批准 profile 的适用指标均有可信证据且无新增硬失败。
- `WATCH`：信号可计算且未命中硬条件，但趋势、非阻塞差异或剩余窗口需要继续观察。
- `STOP_RECOMMENDED`：命中已批准的在线硬停止规则、确定性 P0、ND-P0，或权限、安全、计费、核心计算、数据写入等定性硬失败。
- `NOT_APPLICABLE`：有批准依据表明当前阶段无需在线 Agent 信号。

`STOP_RECOMMENDED` 先冻结阶段推进并附样本、窗口、切片和证据；它不表示已停止或回滚。只有 `$release-gatekeeper` 能结合当前阶段与回滚 profile 决定 `NO_GO`、保持、升级或 `ROLLBACK`。

## 缺陷分域

| 等级 | 语义 | 门禁 |
| --- | --- | --- |
| `ND-P0` | 核心业务整体不可用，或存在严重计算、安全、权限、计费或数据风险 | 立即 `FAIL` 并发停止建议 |
| `ND-P1` | 高频核心语义、上下文、推荐、工具规划或格式错误 | 修复并回归后才准出 |
| `ND-P2` | 非核心场景偶发且主流程仍可用 | 记录风险并计划修复 |
| `ND-P3` | 体验、话术或长尾优化 | 进入优化队列 |

稳定复现的 API、服务、脚本或工具接口故障使用确定性 P0-P4；健康接口上的偶发规划、漏调、参数编造或结果误用使用 ND 分类。两套编号并存，不互相覆盖。
