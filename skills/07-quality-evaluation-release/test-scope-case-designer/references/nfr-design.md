# NFR 范围与用例设计

把“快、稳、安全、可恢复、可运维”等描述转成可测试、可追溯的判据。每条规则记录 `source_ref`、`approval_status` 和 `scope`；仓库基线或行业经验不能自动成为项目门禁。

易用性描述任务完成、错误恢复和学习成本；服务可用性描述技术成功口径，二者不得混用。

## 设计流程

1. 列出服务、接口、客户端、数据、队列、缓存、模型、Prompt、工具、知识库、依赖和区域。
2. 按业务影响、发生可能性、变更触达和可恢复性选择质量属性。
3. 查找批准的需求、SLI/SLO/SLA、容量、安全、合规、支持矩阵和历史基线。
4. 为每项 NFR 定义指标、范围、公式、负载/故障、窗口、环境、数据、证据和门禁动作。
5. 设计稳态、边界、峰值、突发、长稳、依赖异常、资源饱和、降级、恢复和回切场景。
6. 建立“NFR 来源 -> 风险 -> 判据 -> 场景 -> 工具/环境 -> 证据 -> 门禁/回滚”追踪。
7. 由适用角色批准口径并版本化保存。

## 最小判据契约

| 字段 | 必须回答的问题 |
| --- | --- |
| 来源与批准 | 哪份可核验记录批准了什么？ |
| 对象与范围 | 哪个服务、区域、客户端、模型或用户群？ |
| 指标与公式 | 分子、分母、错误分类、排除项和聚合？ |
| 单位与方向 | 单位是什么，越高还是越低越好？ |
| 负载/故障 | 并发、到达率、数据分布、时长和依赖状态？ |
| 统计口径 | 百分位、窗口、样本量和置信信息？ |
| 环境与数据 | 拓扑、配置、数据版本和时间同步？ |
| 目标与动作 | 目标、警戒、停止/回滚值和批准人？ |
| 证据与责任 | 原始数据、查询、日志/Trace、责任人和复测条件？ |

SLI 是测量口径，SLO 是批准窗口内的目标，发布/回滚阈值是一次版本的操作条件；三者不能自动互换。

## 域与代表方法

| NFR 域 | 代表性方法 | 关键证据 |
| --- | --- | --- |
| 性能/容量 | 基线、阶梯、峰值、突发、长稳、容量拐点 | 原始样本、百分位、错误率、资源/队列和配置 |
| 可用性/可靠性 | 长稳、重试/超时、依赖失败、重复执行 | SLI、时间线、失败分类和恢复记录 |
| 韧性/恢复 | 隔离环境故障、降级、备份恢复、切换/回切 | 注入清单、告警、RTO/RPO、数据校验 |
| 安全/隐私 | 鉴权授权、攻击面、脱敏和审计 | 范围、规则、人工复核和审计日志 |
| 兼容/数据 | 客户端/协议/Schema 矩阵、幂等、对账和回放 | 支持矩阵、事件序列、校验和与快照 |
| 可观测/可运维 | 指标、日志、Trace、告警路由和演练 | 查询、告警送达、Trace 和 Runbook |
| 易用/无障碍 | 任务完成、错误恢复、批准标准与辅助技术 | 任务记录、检查报告和人工复核 |
| 成本效率 | 固定质量下的单位成功成本和重试放大 | 用量来源、分摊公式、质量与成本基线 |

排除任何域时记录依据、剩余风险、所有者和重新纳入条件。

## Agent NFR

至少按适用范围拆分端到端/模型/检索/工具延迟，并覆盖并发、限流、上下文长度、Token、工具失败、坏 Schema、降级、恢复、质量保持、安全和漂移。技术失败与有效语义运行必须分开统计；性能或成本改善不能抵消计费、权限、安全或核心业务错误。

重复采样、质量指标和统计门禁交给 `agent-nondeterministic-evaluator`；本技能只提出范围、风险和判定需求。

## 缺失与冲突

- 历史值和工具默认值只能标为基线，不能升级为 SLO。
- 缺少目标时可给测量计划，但状态为 `UNAPPROVED`。
- 缺少口径、环境、负载模型或窗口时，即使有数字也不能判定通过。
- 多份批准标准冲突时比较适用范围和口径，交由责任人裁决。

输出至少包含 NFR 来源/批准、对象、风险、SLI/公式、目标/窗口、负载/故障、环境/数据、场景、证据、排除项和责任人。
