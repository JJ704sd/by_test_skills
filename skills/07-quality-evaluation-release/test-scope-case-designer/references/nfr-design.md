# NFR 范围与判据

把质量描述转成可测试证据。每条规则记录 `source_ref`、`approval_status`、`scope`；历史值、行业经验和工具默认值只能作为基线，不能自动成为门禁。

## 设计流程

1. 识别服务、客户端、数据、队列、模型、Prompt、工具、依赖和区域。
2. 按影响、可能性、触达和可恢复性选择质量属性。
3. 查找批准的需求、SLI/SLO、容量、安全、合规、支持矩阵和基线。
4. 定义指标、公式、方向、单位、窗口、负载/故障、环境、数据、证据和门禁动作。
5. 设计稳态、边界、峰值、长稳、依赖异常、降级、恢复和回切场景。

| 判据字段 | 必须明确 |
| --- | --- |
| 来源与范围 | 批准记录、对象、版本、区域、客户端或用户群 |
| 指标 | 分子、分母、公式、单位、方向、聚合与排除 |
| 模型 | 负载、故障、数据分布、窗口、环境和样本要求 |
| 动作 | threshold/profile 引用、缺失策略、警戒、停止/回滚和责任人 |
| 证据 | 原始数据或查询、日志/Trace、复测和失效条件 |

SLI、长期 SLO 与发布/回滚条件是不同契约，不能自动互换。缺少批准阈值时可给测量计划并标 `UNAPPROVED`；缺少公式、环境、模型、窗口或可信证据时不得判通过。

性能、可靠、恢复、安全、兼容/数据、可观测、易用和成本按适用风险选择。Agent 还要拆分技术与有效语义运行、模型/检索/工具链、限流、Schema、降级、安全和漂移；高风险有效失败不能被平均值或成本改善抵消。
