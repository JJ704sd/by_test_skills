# 回归层级模型

项目策略优先；本参考只提供 smoke、core、full 的选择基线。测试范围设计者选择层级并记录来源、适用范围、排除项、风险和批准状态；测试流程只执行和判定准出，发布门禁只消费证据。

## 选择原则

1. 所有版本覆盖变更点、修复点及其直接影响。
2. 上下游、依赖接口、共享组件、历史逃逸点和高频路径按风险纳入。
3. 核心流程、CP0/CP1 和高可用链路至少进入 core。
4. 选择最小充分层级；排除项必须有证据、剩余风险、责任人和重新纳入条件。

## 层级

| 层级 | 最小范围 | 典型适用 |
| --- | --- | --- |
| `smoke` | 启动、登录或入口、核心 happy path、关键 API/工具调用 | 所有候选版本的快速可信度检查 |
| `core` | smoke + 变更/修复点 + CP0/CP1 + 受影响上下游与常见失败路径 | 日常迭代、Hotfix |
| `full` | core + 全部批准用例 + 兼容、边界、异常、恢复及适用 NFR | 大版本、重构、长期未发布或高风险迁移 |

Agent、Web、API 和数据系统用同一层级语义，但具体用例、采样、环境和阈值由对应范围与评测设计决定。不得用固定条数或时长替代风险证据。

## 输出

记录版本、层级、包含与排除、用例和数据版本、环境矩阵、执行轮次、判据、批准来源、剩余风险和触发重新评估的变化。`$test-execution-governor` 的 `lifecycle_gate` 模式消费该记录，不能自行缩减层级；`$release-gatekeeper` 发现证据失效时只能阻断并请求重新评估。
