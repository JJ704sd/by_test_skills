# 风险驱动范围策略

## 界定步骤

1. 收集需求、原型、接口、配置、代码、数据和发布差异。
2. 分析上下游、依赖、共享组件、用户路径、历史逃逸和恢复能力。
3. 按影响、可能性、变更触达和可恢复性分级，记录证据而非只写标签。
4. 选择测试类型、深度、环境、数据和证据需求。
5. 输出包含、排除、假设、未知、责任人、估算和重新评估条件。

高风险至少包括核心业务、资金/计费、权限、安全、敏感数据、不可逆写入、核心 Agent 行为和重大契约变化。低风险不等于免测；先排除隐藏的数据、权限、依赖、监控和回滚影响。

## 测试类型边界

| 类型 | 纳入条件 | 关键关注 |
| --- | --- | --- |
| 功能/接口 | 用户行为、业务规则、API 或依赖契约变化 | 正常、错误、边界、鉴权、幂等、超时和恢复 |
| 兼容 | 客户端、浏览器、设备、OS、协议或 Schema 有支持矩阵 | 使用项目批准并版本化的矩阵；无矩阵时列为待决策，不推定版本 |
| 性能/容量 | 容量、架构、核心路径或基线可能变化 | 负载模型、百分位、错误、资源、停止和恢复 |
| 安全/隐私 | 外部输入、权限、资金、用户数据或工具访问 | 授权、攻击面、脱敏、审计和人工复核 |
| 自动化 | 稳定、高频、高价值且 Oracle 清晰 | 接口优先；无法自动化时记录人工补偿，不设无来源覆盖率 |
| Agent 非确定性 | 模型、Prompt、规则、工具、知识或语义行为变化 | 多样性、上下文、对抗、一致性和批准采样 |

不得在生产执行主动安全扫描、压测或破坏性故障注入。兼容版本、覆盖目标、性能阈值和执行频率必须来自适用的批准 profile。

每个范围项记录对象、变更、风险依据、类型、深度、环境/数据、用例、责任人和证据；每个排除项记录原因、剩余风险、批准/责任人和重新纳入条件。
