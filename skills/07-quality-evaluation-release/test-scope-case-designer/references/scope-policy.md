# 测试范围基线规则

本文件整理自《测试范围界定与测试用例设计指南》（2026-05-07）。项目标准与本基线冲突时，记录来源并采用更严格的适用规则。

## 范围界定步骤

1. 收集需求、原型、接口、配置、代码和发布差异。
2. 分析上下游、依赖服务、数据流、历史易错点和高风险区域。
3. 评定风险，明确发生可能性、影响和证据。
4. 选择测试类型、深度、工具/环境需求和资源。
5. 输出包含项、排除项、假设、责任人和工作量。

## 风险与默认深度

| 风险 | 判定特征 | 默认深度 |
| --- | --- | --- |
| 高 | 核心业务；资金/计费、权限、敏感数据或安全；用户量大；核心 Agent 逻辑/模型；架构或核心接口变更；历史高发 | 全量功能、核心接口、自动化回归，并按风险执行性能基线、安全专项、兼容和人工复核 |
| 中 | 次要功能、局部接口/界面、偶发场景，影响可控且有回退 | 核心功能回归、接口全量、基础安全扫描/兼容检查 |
| 低 | 文案、日志格式、非核心体验优化，且无权限/数据/依赖影响 | 冒烟与受影响模块回归；保留排除依据 |

风险低不等于不测试。先检查是否隐藏影响权限、数据、接口契约、监控或回滚能力。

## 测试类型边界

### 功能

- 所有版本都评估新增、修改、主流程、异常、边界和回归。
- 覆盖业务规则和用户可见行为；不要用功能测试替代性能、安全或代码内部验证。
- 优先核心链路、用例优先级 CP0/CP1、失败路径、取消/重试和恢复；缺陷严重度另用 P0/P1。

### 接口

- 前后端分离、微服务、第三方调用或 API 变更时必测。
- 覆盖状态码、响应结构、业务错误码、鉴权、参数边界、幂等、超时、重试和依赖失败。
- 每次发布前回归核心接口并达到 100% 覆盖；接口新增、修改或删除后覆盖契约和上下游影响。
- 静态资源和第三方内部实现可排除，但要说明边界；团队应至少保留一次全量接口触达记录。

### 兼容性

- Web/移动端按实际用户矩阵覆盖浏览器、设备、OS、分辨率和网络。
- 没有项目批准矩阵时，Web 可用原规范的 Chrome、Edge、Safari“最新两个版本”作为待确认草案；输出时必须解析为具体版本号、查询/验证日期和来源，无法核实时标为待确认。移动端“主流 iOS/Android”同样必须物化为具体版本、设备和分辨率。已有用户数据或兼容标准时采用更严格的适用矩阵。
- 聚焦登录、核心流程、支付/提交、文件上传等关键路径。
- 极低版本或极少用户设备可排除，但要有用户数据或产品决策支持。

### 性能

- 大版本、架构升级、核心接口重构、预计容量增长或线上性能问题后执行。
- 先定义并发、Ramp-up、持续时长、压力/容量模型、数据模型、基线和停止条件。
- 观察 P90/P95/P99、TPS、错误率、CPU、内存、数据库、缓存和依赖服务。
- 核心指标相对基线劣化超过 20% 时必须分析并评估是否阻塞；具体绝对阈值由项目 SLA/容量目标批准。

### 安全

- 对 Web、公开 API、用户数据、支付/计费、权限、外部服务和大版本执行安全评估。
- 至少覆盖未登录、弱凭据/过期 Token、水平/垂直越权、SQL/命令注入、XSS、传输加密、敏感数据泄露和日志脱敏；Agent 增加 Prompt 注入、越狱和工具权限绕过。
- 仅在显式隔离的非生产环境使用自动扫描覆盖基础问题；支付、权限、用户数据等关键模块还需经授权的人工安全验证/渗透评估。审批不能把扫描或渗透目标转移到生产。
- Demo 或隔离内网功能只有在无敏感数据且风险已批准时才可缩小范围。

### 自动化

- 优先稳定、高频、高价值、可重复且断言清晰的用例；接口优先于 UI。
- 原规范中的 P0/P1 用例优先级在本技能输出中映射为 CP0/CP1：CP0 自动化目标 100%，CP1 目标至少 70%；无法自动化时记录原因和人工补偿。它们不是缺陷严重度。
- UI 自动化聚焦登录、冒烟和稳定主链路；不把一次性验证、高变更 UI、复杂拖拽或无断言录制脚本纳入长期回归。

### 易用性/UX

- 新产品、核心交互大改、用户反馈差或 Agent 话术变化时纳入。
- 测试关注文案一致性、错误提示、操作逻辑和流程闭环；用户访谈、满意度和正式可用性研究由产品/设计主导。

### Agent 非确定性

- 所有 Agent 项目都覆盖实体/单位、计算、推荐、格式、鲁棒性、一致性、上下文、幻觉和安全。
- 按变更与风险覆盖不同模型版本、输入/上下文长度、工具/Schema 版本和支持配置的兼容性；具体矩阵需版本化。
- 它不能替代 API 连通、服务可用、工具错误和 UI 基础测试。
- 用例设计写明重复采样和判定口径；正式评估交给 `agent-nondeterministic-evaluator`。

## 范围清单字段

每个范围项至少记录：对象、变更、风险及依据、测试类型、深度、优先级、环境/数据、用例或场景、负责人、预计工作量和证据。每个排除项至少记录原因、剩余风险、批准/责任人和重新评估条件。

工作量至少基于用例数、执行轮次、自动化覆盖目标、环境组合、数据准备和人工复核量估算。不要只给无依据的人日。
