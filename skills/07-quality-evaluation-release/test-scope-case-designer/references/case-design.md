# 用例设计方法

| 场景 | 方法 | 关注 |
| --- | --- | --- |
| 单字段 | 等价类、边界值 | 有效/无效、空、极值、超长和特殊字符 |
| 流程/状态 | 场景法、状态转换 | 正常、失败、取消、重试、恢复和非法跳转 |
| 多条件 | 判定表、因果图 | 组合、互斥、优先级和结果 |
| 多环境 | 风险优先组合 | 批准矩阵中的主流与高风险组合 |
| Agent | 多样性、上下文、对抗、一致性 | 改写、缺省、插话、长上下文、越权和重复采样 |

先建立“判据 -> 等价类/状态/组合 -> 代表数据”骨架。前置、步骤、Oracle 和清理相同且仅输入变化时使用参数化用例；权限、副作用、恢复或判定不同则拆分。每个数据行保留稳定 ID、来源、期望、风险和版本。

`representative_cases` 只交付骨架和代表行；`baseline_ready` 才按 [用例模板](../assets/case-templates.md) 展开。Agent baseline 拥有场景、风险、输入意图、判据和批准的 sampling profile，但不拥有可执行数据集、runner 或 Judge。

计费、计算、权限、安全和关键数据必须使用确定性规则或人工复核；LLM 评分不能独占高风险判定。评审时确认每项高风险影响有用例或正式排除，正常/异常/边界/恢复有可观察判据，最终产物没有占位符、无来源数字或虚构批准。
