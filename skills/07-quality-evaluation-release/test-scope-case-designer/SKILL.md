# 测试范围与用例设计

## 决策权

负责范围、排除项、风险依据、可测判据、用例和追踪关系；不虚构执行结果。产品、业务、架构、安全或运维等适用角色批准 NFR/SLO 和风险接受标准，本技能只记录来源、暴露缺口并物化判据。

- 测试阶段与准出交给 $test-process-governor。
- 工具、环境和权限方案交给 $test-tool-governor。
- Agent 采样、指标和基线结论交给 $agent-nondeterministic-evaluator。
- 回归层级、发布、灰度和回滚交给 $release-regression-gatekeeper。

## 交付深度

- scope_only：给出风险、包含/排除、测试类型、深度和估算，不展开完整用例。
- representative_cases：补充覆盖骨架、代表性参数化用例和关键判据。
- baseline_ready：用户明确需要可入库基线时，才生成完整追踪、字段、评审和版本信息。

## 工作流

1. 加载上一版范围或用例快照；按新增、修改、删除整理需求、代码、配置、接口、数据、依赖及 Agent 组件变化。
2. 从变更点追踪上下游、共享组件、权限、资金、数据、高频路径和历史逃逸点。
3. 对每个对象记录风险等级、可能性、影响和依据；读取 [scope-policy.md](references/scope-policy.md) 选择默认深度。
4. 将功能、接口、NFR 和 Agent 非确定性标为必测、按需或排除；排除必须有责任人和重新纳入条件。NFR 场景读取 [nfr-design.md](references/nfr-design.md)。
5. 建立“来源 -> 风险 -> 指标/判据 -> 负载或故障模型 -> 场景/用例 -> 证据”的覆盖关系。
6. 估算用例、轮次、环境组合、自动化和人工复核工作量，并披露假设。
7. 读取 [case-design.md](references/case-design.md)，先产出覆盖骨架和代表用例，再按交付深度展开、评审和基线化。

## 硬规则

- 预期结果必须可观察、可判定，不能只写“正常”或“符合预期”。
- 核心需求覆盖正常、异常、边界及失败后的恢复或重试。
- 资金、计费、权限、安全拒绝、敏感数据和一致性按高风险处理。
- 排除项写明原因、风险所有者和重新评估条件。
- Agent 用例引用批准的采样和阈值；未批准时标为 UNAPPROVED，单次输出不能代表非确定性质量。
- NFR 判据包含来源、公式、单位、窗口、环境、负载或故障模型、证据和门禁动作；本技能不发明阈值。
- 用例应让他人无需隐含知识即可执行；需求、缺陷或版本变化后维护来源和历史。

## 输出与参考

先给范围结论、假设、未知项和重新评估条件。字段、模板、交接包和评审清单统一读取对应 reference，不在正文复制。
