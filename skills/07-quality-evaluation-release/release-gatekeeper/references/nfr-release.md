# NFR 发布证据

每项 NFR 记录 `source_ref`、`approval_status`、`scope` 和 threshold/profile 引用。长期 SLO、错误预算、阶段门禁和硬回滚规则是不同契约，不能自动互换。

发布前至少核验对象、SLI 公式、目标/窗口、环境差异、负载/故障、当前值、可比基线、阈值、趋势、样本、错误分类、遗留风险、生产查询、告警、值守、停止和恢复证据。

| 域 | 关键证据 |
| --- | --- |
| 性能/容量 | 目标负载、聚合、错误、资源余量和环境差异 |
| 可用/可靠 | SLI、依赖失败、长稳、错误预算和区域拆分 |
| 韧性/恢复 | 降级、切换/回切、回滚演练、RTO/RPO 和验证 |
| 安全/隐私 | 权限、拒绝、脱敏、审计、告警和值守 |
| 兼容/数据 | 客户端/Schema、迁移、回放、对账和回滚兼容 |
| 可观测 | 指标、日志、Trace、查询、告警送达和 Runbook |
| Agent | 离线门禁、组件运行信号、工具、语义、安全和漂移 |

数据库或 Schema 变化不能假设代码回滚即可恢复数据。不可逆迁移必须有快照/备份、对账、兼容或经批准的向前修复，并验证恢复。

每阶段冻结版本、配置、流量/白名单、窗口、样本、指标、基线、阈值和操作人。核心、业务、安全、Agent、数据、隐私和监控任一适用硬失败都不得被平均值抵消；profile、观测或版本不可核实时不得推进。

命中硬条件时停止推进、保全证据并按批准方案恢复，随后验证核心链路、数据/Schema、权限、安全、关键 NFR 和告警。回滚不安全或失败时保持停止并升级事故指挥。
