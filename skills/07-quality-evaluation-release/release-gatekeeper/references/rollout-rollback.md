# 放量、Hotfix 与回滚

## Rollout profile

每个阶段在开始前批准并冻结：`stage_id`、版本/配置、流量或人群选择、evaluation window、minimum sample、threshold profile refs、切片、监控、缺失数据策略、推进/保持/停止/回滚动作、operator、approval ref 和 evidence query。未物化的比例、时长或模糊条件不能开始阶段。

阶段推进要求全部适用核心哨兵、业务、Agent、数据、安全和监控证据满足 profile，上一阶段异常已闭环且阶段 owner 已确认。无法按流量比例隔离时可使用批准的白名单、版本或路由策略，但不能取消门禁。

## Hotfix

仅在严重生产故障无法通过安全配置切换或直接回滚恢复，且修复收益高于紧急变更风险时使用。必须保留部署前在线授权、最小充分测试、影响说明、监控、恢复能力和事后审批/复盘；组织角色与顺序来自当前应急流程，不在本仓库固定。

## 定性硬回滚

命中任一适用条件即停止推进并按批准恢复方案行动：

- P0、核心功能不可用或服务崩溃。
- 权限、安全、计费、核心计算、数据完整性或隔离失败。
- Agent 无响应、危险规划/工具调用或核心语义命中批准硬规则。
- 错误、延迟、资源、告警或业务信号突破批准 threshold profile。
- 版本/配置漂移、关键观测失真，且 profile 的 missing-data policy 要求回滚。

不要等待观察窗口结束或把命中规则改写为“启动回滚决策”。若回滚本身不可安全执行，保持停止、升级事故指挥并采用经授权的替代恢复方案。

## 恢复

停止发布/放量并通报版本和影响；由授权 operator 恢复稳定版本/配置或执行批准的向前修复；验证核心流程、数据、权限、安全、Agent 和关键 NFR；观察至满足恢复 profile；归档实际动作、恢复点、遗留项和重新发布条件。动作未完成或恢复未验证时不得关闭。
