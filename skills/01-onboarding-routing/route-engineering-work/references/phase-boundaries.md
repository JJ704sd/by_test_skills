# Phase Boundaries

A phase ends when one coherent chunk of work—such as discovery, implementation, or QA—is complete. Decide how to continue at that boundary, not in the middle of the phase.

## Choose in this order

1. **Continue in the current session** when the next phase needs the full reasoning as a primary source and enough context remains.
2. **Clear the context** when the current phase is irrelevant to what comes next.
3. **Use `$handoff`** when work must move to another harness, directory, repository, colleague, or a separately resumed side task.
4. **Use a subagent** when the task is tightly scoped, can run without steering, and should report back into the current session.
5. **Compact the context** when relevant reasoning must remain, the work stays in the same place, and the user still needs to steer.

Continuing preserves the complete primary source. Every other option trades detail for room or portability, so use the first applicable choice rather than defaulting immediately to a summary.

If the need to split appears mid-phase, either continue or delegate a bounded side task. Wait for a true boundary before clearing or compacting the main context.
