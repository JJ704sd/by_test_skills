## 适用边界与来源层级

本文件用于把“快、稳、安全、可恢复、可运维”等模糊描述转成可测试、可追溯的 NFR。

来源层级必须在输出中使用以下枚举：

1. **`primary_spec`（本技能主规范）**：《测试范围界定与测试用例设计指南》明确的性能、安全、兼容、易用性、数据一致性/幂等、可执行用例和 Agent 场景要求。
2. **`cross_spec`（其余配套规范）**：流程规范的性能/稳定性目标与阶段证据、工具规范的日志/监控与 Trace、发布规范的高可用链路/Agent 延迟/灰度回滚、Agent 规范的工具稳定性/在线观察及“服务可用性由通用流程覆盖”的交接要求。
3. **`project_approved`（项目批准）**：需求、架构、SLA/SLO、安全或合规标准中已批准的指标与阈值。
4. **`governance_enhancement`（治理增强）**：容量余量/伸缩、故障注入、熔断、RTO/RPO、错误预算、产品可维护/可测试性、完整隐私合规、无障碍和运行成本等五份规范未完整定义的方法。

`cross_spec` 必须记录具体规范和版本，不能笼统写“原规范”。`governance_enhancement` 用于发现遗漏，不能被表述成 PDF 已有硬性阈值。项目没有批准阈值时，只能输出待确认的指标草案和验证计划，不能判定通过。

原范围指南中的“易用性/可用性”描述的是 usability（任务完成、错误提示和学习成本），不是服务 availability；本文件始终分别使用“易用性”和“服务可用性”，不得互相代替。

## NFR 设计流程

1. **建立对象清单**：列出服务、接口、客户端、数据存储、队列、缓存、模型、Prompt、工具、知识库、第三方依赖和部署区域。
2. **识别质量属性**：逐对象检查性能/容量、可用性/可靠性、韧性/恢复、安全/隐私、兼容、可观测、可维护/可测试、数据完整性、体验/无障碍和成本。
3. **追踪业务影响**：说明属性失败会影响哪些用户、核心链路、资金、权限、数据、安全承诺或恢复能力。
4. **确认权威口径**：找到已批准的需求、SLI/SLO/SLA、架构容量、合规标准、支持矩阵和历史基线；记录版本与批准人。
5. **量化判据**：为每项 NFR 补齐指标、公式、范围、负载/故障模型、统计窗口、环境、数据、证据和门禁动作。
6. **设计场景**：覆盖稳态、边界、峰值、突发、长稳、依赖异常、资源饱和、恢复、降级和回切；只选择与风险有关的组合。
7. **建立追踪**：形成“NFR 来源 -> 风险 -> SLI/SLO -> 场景/用例 -> 工具/环境 -> 证据 -> 门禁/回滚”的链路。
8. **评审与基线化**：由需求/产品、研发/架构、测试、运维/SRE、安全等适用角色确认口径；版本化保存。

## 量化一条 NFR

每条可执行 NFR 至少包含以下字段：

| 字段 | 必须回答的问题 |
| --- | --- |
| 来源与版本 | 指标来自哪份需求、SLO、标准或批准记录？ |
| 对象与范围 | 哪个服务、接口、区域、客户端、模型或用户群受约束？ |
| 指标与公式 | 分子、分母、排除项、聚合方式和错误分类是什么？ |
| 单位与方向 | ms、s、RPS、百分比、次数、字节、Token 或成本；越高还是越低越好？ |
| 工作负载/故障模型 | 并发、到达率、数据分布、持续时长、依赖状态和注入方式是什么？ |
| 统计口径 | 百分位、滑动窗口、自然周期、样本量和置信信息是什么？ |
| 环境与数据 | 使用哪个隔离环境、拓扑、配置、数据版本和时间同步方式？ |
| 目标与门禁 | 目标值、警戒值、硬停止/回滚值及其批准人是谁？ |
| 证据与责任 | 原始数据、仪表盘、日志/Trace、报告位置、责任人和复测条件是什么？ |

区分三个概念：

- **SLI** 是实际测量值及其计算口径。
- **SLO** 是在指定统计窗口内批准的目标。
- **发布门禁/回滚阈值** 是针对一次版本或灰度阶段的操作条件，不应自动等同于长期 SLO。

可使用下列公式骨架，但不得自行填入目标值：

- 可用性 = 成功且满足有效性定义的请求数 / 纳入统计的有效请求数。
- 错误率 = 归入错误口径的请求数 / 纳入统计的有效请求数。
- 延迟 = 端到端、服务端、模型和工具耗时分别统计 P50/P95/P99 等批准百分位。
- 吞吐/容量 = 在给定负载、数据和资源配置下，满足延迟与错误约束的完成量。
- RTO = 从确认中断到服务恢复至批准状态的时间。
- RPO = 恢复后相对于故障点可接受的数据损失时间或数据量。
- 追踪覆盖率 = 可关联到完整 Trace 的纳入请求数 / 纳入请求数。
- 单次成功成本 = 纳入的计算、模型、工具或基础设施成本 / 成功完成量。

## NFR 分类与测试方法

| NFR 域 | 典型风险 | 代表性方法 | 关键证据 |
| --- | --- | --- | --- |
| 性能、容量、可扩展性 | 延迟、排队、资源饱和、扩缩容振荡 | 基线、阶梯、峰值、突发、长稳、容量拐点 | 原始样本、百分位、错误率、资源/队列曲线、配置快照 |
| 可用性、可靠性 | 间歇故障、长稳失败、依赖抖动 | 长稳、重试/超时验证、依赖故障场景、重复执行 | SLI 口径、时间线、成功/失败分类、恢复记录 |
| 韧性、降级、恢复 | 局部故障扩大、错误降级、无法回切 | 仅在隔离环境进行故障注入、熔断/隔离、备份恢复、切换/回切演练 | 注入清单、告警、降级输出、RTO/RPO、数据校验 |
| 安全、隐私、合规 | 越权、注入、泄露、审计缺失 | 鉴权/授权、输入攻击面、数据流和日志脱敏、审计验证 | 扫描/人工证据、权限矩阵、脱敏抽检、审计日志 |
| 兼容、互操作 | 平台、协议、Schema 或版本组合失败 | 风险驱动的客户端/OS/协议/依赖矩阵、前后向兼容 | 支持矩阵、组合结果、契约与迁移证据 |
| 可观测、可运维 | 故障不可发现或不可定位 | 指标/日志/Trace 完整性、告警路由、演练、关联 ID | 仪表盘、告警送达、Trace 样本、Runbook |
| 可维护、可测试 | 修改困难、证据不可复现 | 配置外置、可注入依赖、可重复数据、诊断性和自动化接口检查 | 版本化脚本、配置、数据、失败诊断与复跑记录 |
| 数据完整性、一致性 | 丢失、重复、乱序、跨区域不一致 | 幂等、并发、故障恢复、对账、复制延迟和回放 | 数据对账、事件序列、校验和、恢复前后快照 |
| 易用性、无障碍 | 关键任务不可完成、错误不可理解 | 任务完成、错误恢复、键盘/读屏/对比度等项目批准标准 | 任务记录、辅助技术矩阵、问题证据 |
| 成本与效率 | Token/调用/资源无界增长 | 固定质量下的单位成本、缓存/重试放大、预算压力场景 | 用量明细、成功口径、质量并行结果、成本基线 |

上述方法不是全部必测。按业务影响、发生可能性、变更触达和可恢复性选择；排除时记录风险所有者和重新纳入条件。

## 覆盖矩阵与优先级

高优先级通常包括：

- 核心交易、计费、权限、安全拒绝、敏感数据与数据一致性。
- 单点依赖、容量接近上限、历史事故点和跨区域/迁移路径。
- 失败时可能静默产生错误结果而不是显式报错的降级路径。
- 无监控、无回滚或恢复时间未知的组件。

覆盖矩阵不得只列 NFR 名称。至少关联：

```markdown
| NFR-ID/来源 | 对象/用户旅程 | 风险 | SLI/公式 | 目标与窗口 | 负载/故障模型 | 场景/用例 | 环境/数据 | 工具能力 | 证据 | 门禁动作 | 责任人 | 状态 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
```

每个“必测”NFR 至少覆盖稳态和一个风险相关的异常/恢复场景；核心路径还应检查异常期间是否会产生错误数据、越权或不安全输出。

## Agent 的 NFR 设计

Agent NFR 不能只测端到端平均延迟。至少按适用范围拆分：

- 端到端、模型、检索、工具调用和编排延迟。
- 并发/吞吐、限流、队列、上下文长度与资源/Token 使用。
- 模型或工具超时、5xx、限流、坏 Schema、陈旧/冲突数据和部分失败。
- 工具成功率、重试放大、熔断/降级状态和恢复行为。
- 负载或降级状态下的语义质量、安全拒绝、Schema 和关键业务正确性。
- Prompt、模型、工具、知识库、区域和时间维度的可观测性与漂移。

必须把技术失败与有效语义运行分开统计。性能改善、成本下降或总体平均成功率，不能抵消一次有效的计费、权限、安全或核心业务错误。

重复采样、质量指标和统计门禁交给 `agent-nondeterministic-evaluator`；这里负责提出范围、风险和判定需求。

## 缺失阈值与冲突处理

- 不得把行业经验、历史值、工具默认值或示例值写成项目已批准目标。
- 只有历史基线时，标为“基线”，不能自动升级为 SLO 或发布门禁。
- 缺少目标时输出 `待批准`，同时给出建议测量方法、所需数据和批准角色。
- 缺少口径、环境、负载模型或统计窗口时，即使有数字也不能判定通过。
- 多份批准标准冲突时列出冲突、适用范围和版本；交由责任人裁决。在高风险门禁形成前保持待确认或采用适用规则中明确要求的更严格值。
- 任何补充治理项都必须标注为建议，不能伪装成 PDF 原文要求。
