## 适用边界

本文件补齐 NFR 从设计到测试准出的证据链，输出必须标记来源层：

- `primary_spec`：《测试流程规范》明确的环境/服务/依赖就绪、冒烟、执行证据、环境不稳暂停和测试准出。
- `cross_spec`：范围规范的性能/安全/兼容/数据要求、工具规范的日志/监控、发布规范的稳定版本恢复/线上观察，以及 Agent 规范明确移交给通用流程的服务可用性。
- `project_approved`：项目批准的 NFR/SLO、容量、恢复、安全或合规要求。
- `governance_enhancement`：统一 SLI/SLO 证据模型、故障注入、RTO/RPO、错误预算、产品可维护/可测试性、无障碍和成本等五份规范未完整定义的方法。

不得把 `cross_spec` 或 `governance_enhancement` 冒充流程规范原文。

本技能只治理测试阶段证据。NFR 范围和判据设计交给 `test-scope-case-designer`，工具与环境交给 `test-tool-governor`，生产发布与回滚交给 `release-regression-gatekeeper`。

## 阶段链路

| 阶段 | 必需输入 | 必做动作 | 输出/证据 | 门禁 |
| --- | --- | --- | --- | --- |
| 需求评审 | NFR 来源、对象、风险、批准角色 | 检查是否量化、可测试并有来源 | NFR 清单、未知项、批准状态 | 高风险 NFR 无负责人或无判定口径时不得称为就绪 |
| 测试设计 | SLI/SLO/门禁、负载或故障模型 | 建立 NFR 覆盖矩阵、环境/数据/工具计划 | 用例、追踪、估算、排除项 | 必测项无场景、证据或恢复判据时退回 |
| 提测准入 | 构建、配置、隔离环境、可观测能力 | 核对拓扑、数据、权限、监控、停止条件 | 环境基线、配置快照、试运行 | 环境不可信或可能影响生产时不准入 |
| 测试执行 | 冻结版本和已评审计划 | 记录原始数据、时间、版本、负载、故障和异常 | 原始结果、日志/Trace、报告、缺陷 | 证据丢失、采集失真或环境漂移时暂停/重跑 |
| 测试准出 | 结果、缺陷、复测、遗留风险 | 逐 NFR 对照目标和硬门禁 | NFR 结论矩阵、偏差、签署 | 高风险失败、关键目标未批准或证据不足不得通过 |
| 发布交接 | 测试准出与回滚关注点 | 交付生产监控、阶段阈值和验证项 | 证据包、遗留风险、发布建议 | 由发布门禁形成最终 Go/No-Go |

## NFR 就绪度

提测前逐项核对：

- [ ] NFR 来源、版本、范围和批准状态可追溯。
- [ ] SLI 公式含分子、分母、错误分类和排除项。
- [ ] SLO 或测试目标含数值、单位、百分位/窗口和适用对象。
- [ ] 工作负载、数据分布、持续时长、故障模型和恢复目标已定义。
- [ ] 测试环境与生产目标拓扑的相同点、差异和限制已说明。
- [ ] 工具、采集、时间同步、日志/Trace 和报告路径已试运行。
- [ ] 不在生产执行压测、安全扫描、破坏性故障注入、删除或修改操作。
- [ ] 安全、隐私和数据清理要求已落实。
- [ ] 停止条件、恢复步骤、值守和责任人明确。
- [ ] 排除项有剩余风险、风险所有者和重新评估条件。

缺少数字本身不等于测试环境阻塞：可以先测基线或容量曲线；但缺少批准目标时不能输出“达标/通过”。

## 执行证据

每次 NFR 执行至少记录：

- 被测版本、配置、拓扑、区域、依赖、工具/脚本/数据版本和时间区间。
- 预热、负载、并发/到达率、持续时间、数据分布与客户端来源。
- 注入的故障、开始/结束时间、影响对象和恢复动作。
- 原始样本、聚合公式、百分位/窗口、错误分类、资源与队列曲线。
- 指标、日志、Trace、告警和业务结果之间的关联 ID。
- 计划/实际偏差、工具限制、丢样、重试、无效运行和人工干预。
- 目标、警戒值、停止值、实际值、结论和证据位置。
- 缺陷、复测、剩余风险、责任人和期限。

只保留截图或汇总数字不足以证明复杂 NFR。至少保留可复核的原始数据或可重复生成结果的查询、脚本和版本快照。

## 问题分域

不要把所有 NFR 异常都登记成产品缺陷：

| 类型 | 判定特征 | 处理 |
| --- | --- | --- |
| 产品/实现缺陷 | 在可信环境和批准口径下违反期望行为 | 按缺陷流程分级、修复、复测和影响面回归 |
| 需求/标准缺口 | 无目标、口径矛盾、范围或错误分类不清 | 记录需求问题，指定批准人；形成门禁前保持待补证据 |
| 环境/工具限制 | 拓扑不等价、采集丢失、负载器饱和、时钟失准 | 暂停可信度判定，修复或披露限制后重跑 |
| 容量/架构风险 | 未违反现有阈值但接近拐点或无恢复余量 | 登记风险和容量/架构行动，不伪造缺陷 |
| 外部依赖异常 | 供应商/模型/工具不可用或契约漂移 | 保留原始失败并验证己方隔离、降级和恢复；不得静默排除 |

## 准出判定

- `通过`：全部必测 NFR 有批准判据、可信证据并达标；高风险缺陷关闭。
- `有条件通过`：仅有规范允许的非阻塞遗留项，且风险已批准并有补偿、责任人和期限。
- `不通过`：任一硬门禁或高风险 NFR 失败，或存在不能接受的数据/安全/恢复风险。
- `暂停`：环境、工具、采集或构建导致结果不可信，或继续执行会扩大风险。
- `待补证据`：关键判据、原始数据、批准或适用范围缺失，尚不能形成结论。

以下情况不得用总体平均值或其他 NFR 达标抵消：安全/隐私失败、越权、错误计费、核心数据错误、不可接受的恢复失败，以及 Agent 的有效高风险语义失败。

测试准出不等同于生产 SLO 已经满足。长期窗口 SLO、灰度阶段指标和生产错误预算由发布流程继续观察。
