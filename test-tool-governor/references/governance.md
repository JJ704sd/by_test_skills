# 工具选型与治理规则

## 决策维度

| 维度 | 必查问题 |
| --- | --- |
| 统一性 | 团队是否已有标准工具？新方案是否造成重复资产或数据孤岛？ |
| 稳定性 | 项目是否持续维护？文档、依赖、升级和企业落地证据是否可靠？ |
| 可维护性 | 是否易于协作、调试、扩展、Review、升级和故障定位？ |
| 自动化能力 | 是否支持批量、重试留痕、统计、报告、基线和 CI/CD？ |
| 场景适配 | 是否满足目标协议、平台、规模，以及 Agent Trace/回放/采样/语义评估？ |
| 成本与迁移 | 许可证、基础设施、培训、脚本迁移、数据迁移和长期维护成本是什么？ |

不要只给无权重总分。列出每个证据、硬约束和关键权衡；安全否决项不允许用平均分抵消。

## 新工具引入

1. 由测试或开发提出场景、缺口和验收目标。
2. 对照统一性、稳定性、维护性、自动化、适配和成本进行评估。
3. 在非核心项目或内部环境试用 1-2 周。
4. 由测试负责人组织评审，决定采用、限定采用或不采用。
5. 正式推广前输出使用规则、模板、迁移计划和培训，并更新团队标准。

## 权限、环境与数据

- 账号个人专用，敏感工具按最小权限申请；禁止共享、转借和共用。
- 显式区分 dev/test/pre/prod；安全默认值应指向隔离环境，配置缺失时失败关闭而非回退生产。
- 对隔离测试环境中的压测、安全扫描和敏感数据操作执行审批与留痕；审批不允许把这些操作转移到生产。
- Secret 使用环境注入或批准的凭据系统；仓库、报告和日志只保存脱敏值。
- 严禁使用测试工具在生产执行压测、容量摸底、扫描、渗透、破坏性故障注入、删除或修改测试操作；审批不能解除。发布系统按已批准方案执行部署/回滚不属于测试工具操作。

## 资产与生命周期

- 将脚本、非敏感配置、测试集、核心集合和报告模板纳入 Git；使用统一命名和目录。
- 核心脚本定期 Review，移除魔法值、脆弱依赖、无断言步骤和生产默认指向。
- 至少每季度检查工具版本和维护状态；安全漏洞及时升级，大版本先在隔离环境验证兼容性。
- 工具停止维护或被替换时，制定脚本/数据迁移、培训、回退和归档计划；旧资产只读保存后再下线。
- 工具异常先检查版本、配置和环境并及时上报；经批准可临时启用备选工具，同时记录偏差和补测要求。
- 发现漏洞或安全风险立即上报，禁止私自利用；把常见故障和处理结论沉淀到团队知识库/FAQ。
- 本地一次性调试脚本不得直接提交主干；转为正式资产前补齐结构、断言、配置隔离、Review 和 CI。
- 废弃由测试负责人提出并评审；完成迁移和通知后，从团队标准中移除旧工具入口。

## 审计清单

- [ ] 工具和版本符合团队标准，或已有引入评审记录。
- [ ] 环境与生产隔离，缺省配置不会指向生产。
- [ ] 个人账号和最小权限已落实，无共享凭据。
- [ ] 仓库、日志、测试集和报告不含 Secret 或未脱敏隐私。
- [ ] 关键断言、原始失败、日志、统计、报告和 CI 路径完整。
- [ ] 性能、安全和故障注入目标是隔离非生产环境，且有审批、值守、停止/恢复和清理方案；生产仅允许发布授权范围内的被动遥测、只读低频健康检查或非破坏性采样。
- [ ] Agent 的 Prompt、模型、参数、工具、知识库、数据集和基线可追溯。
- [ ] 迁移、维护、升级和废弃责任人明确。

正式决策前不得残留占位符、无来源阈值或虚构审批。未知项写 `UNKNOWN` 并使用 `REVIEW_REQUIRED`；安全否决或环境不可信时 `execution_authorization=BLOCKED`。
