## 适用边界与来源层级

本文件的输出必须标记来源层：

- `primary_spec`：《Agent 非确定性测试流程规范》明确的请求成功、响应时间、工具调用、在线质量、基线退化和漂移；它同时明确一般服务可用性由通用测试流程覆盖。
- `cross_spec`：发布规范的 Agent P95、工具成功、灰度和回滚，工具规范的 Trace/耗时/失败记录，范围规范的性能与 Agent 场景，以及流程规范对服务/依赖就绪和 availability 的接盘。
- `project_approved`：项目批准的 Agent 质量、SLO、容量、降级、恢复和成本要求。
- `governance_enhancement`：组件分段延迟、容量/伸缩、系统化故障注入、RTO/RPO、质量-性能联合分析和单位成功成本等五份规范未完整定义的方法。

不得把 `cross_spec` 或 `governance_enhancement` 冒充 Agent 专项规范原文；增强项只有在项目批准后才是硬门禁。

本技能评估 Agent 特有的非确定性质量与运行信号，不替代：

- 服务/API/UI 的确定性可用性和通用性能测试。
- 工具环境、安全权限及生产操作审批。
- 发布阶段的流量控制、停止与回滚执行。

## 运行 NFR 维度

按适用范围分别评估：

| 维度 | 必查对象 |
| --- | --- |
| 成功与可用性 | 请求、有效语义运行、模型、检索、每个工具、Schema 解析和最终任务完成 |
| 延迟 | 端到端、排队、编排、模型首 Token/总耗时、检索、每个工具、重试和后处理 |
| 容量与扩展 | 并发、到达率、队列、限流、上下文长度、批量、区域和资源饱和 |
| 可靠性 | 技术失败、间歇错误、超时、重试、重复调用、工具副作用和长稳趋势 |
| 韧性与恢复 | 模型/工具限流、5xx、慢响应、坏 Schema、部分失败、熔断、降级、回切 |
| 质量保持 | 负载/故障/长上下文下的正确性、约束、幻觉、安全拒绝和格式 |
| 可观测性 | 版本、请求 ID、Trace、模型/工具拆分、错误分类、告警和用户反馈 |
| 成本效率 | 输入/输出 Token、模型/工具调用、重试放大、缓存和每次成功任务成本 |

不要只给全局平均值。至少按版本、场景/风险、模型、工具、区域和负载阶段拆分；具体拆分维度由项目风险决定。

## 指标口径

在运行前冻结指标定义、分母、排除项、统计窗口和项目批准阈值。

- 请求成功率 = 满足批准技术成功定义的请求 / 纳入技术请求。
- 有效运行率 = 可进入语义判定的运行 / 计划运行；技术失败单独列出。
- 有效运行条件下语义成功率 = 满足全部必需语义与业务约束的有效运行 / 有效语义运行。
- 端到端任务成功率 = 同时技术成功且语义/业务成功的纳入运行 / 预先声明的纳入计划运行。被测系统的超时、限流和依赖失败计入失败；评测 runner/采集本身失效应标无效并触发 `BLOCKED`，不得从分母静默删除后继续判门禁。
- 工具成功率 = 指定工具符合调用契约且返回可用结果的调用 / 纳入该工具调用。
- 降级正确率 = 故障期间符合批准降级语义的有效运行 / 纳入降级运行。
- 延迟按端到端和组件分别报告项目批准的百分位；同时记录样本量和时间窗口。
- 重试放大 = 总尝试次数 / 初始请求数，并同时报告重试后的最终成功率。
- 单次成功用量/成本 = 纳入用量或成本 / 成功任务数。

技术成功不等于语义成功；HTTP 2xx、模型返回文本或工具返回响应都不能单独证明任务成功。

工具调用指标必须按工具分别报告，不能用总体平均掩盖一个核心工具失效。重试前原始失败不得从分母或证据中删除。

## 负载与故障场景

在隔离测试环境按风险组合：

1. 低负载基线与缓存冷/热状态。
2. 目标并发/到达率、阶梯升压、峰值、突发和批准时长的长稳。
3. 短、中、长上下文，以及不同输入/输出大小和工具调用深度。
4. 模型超时、限流、5xx、空响应、格式漂移和慢响应。
5. 工具超时、限流、5xx、坏 Schema、陈旧/冲突数据、部分/全部失败。
6. 检索为空、低相关、索引延迟或知识版本不一致。
7. 网络抖动、断连、重复响应、乱序和恢复。
8. 多区域或提供方切换仅在项目架构适用且有隔离环境能力时执行。

生产禁止压测、破坏性故障注入和安全扫描。已批准的线上采样只观察真实流量或非破坏性哨兵，不替代离线故障和容量评测。

每个场景预先声明样本、并发、持续时长、重试策略、随机参数、数据集版本和停止条件；不能看到结果后修改口径以获得通过。

## 质量与性能联合判定

性能、可靠性和成本必须与语义质量并行报告：

| 负载/故障阶段 | 计划/技术失败 | 有效语义运行 | 端到端/条件语义成功率 | 延迟/吞吐 | 高风险失败 | 工具拆分 | 用量/成本 |
| --- | --- | --- | --- | --- | --- | --- | --- |

强制规则：

- 计费、核心计算、权限、安全拒绝、数据写入和对外承诺的一次有效语义失败，不能被更低延迟、更高吞吐或更低成本抵消。
- 技术失败与语义失败分别归因；端到端任务成功率不能静默排除被测系统的超时、限流或依赖失败。
- 候选与基线比较时使用相同数据集、负载模型、统计口径和可比配置；否则标为 `REVIEW_REQUIRED`。
- 负载下样本构成必须与基线可比；若因限流只剩简单样本，不得声称质量保持。
- 缺少项目批准阈值时可以输出曲线和基线，但不能给 `PASS`。

## 降级与恢复

降级必须是批准的业务行为，而不是“系统没有报错”。逐场景验证：

- 是否明确提示暂不可完成、限制范围或数据新鲜度。
- 是否避免捏造、误报价、越权、错误写入或把陈旧数据当事实。
- 是否阻止重复工具副作用和重试风暴。
- 是否遵循熔断、限流、备用路径和人工接管规则。
- 恢复后是否清除错误状态，避免重复、丢失、跨用户或脏数据。
- 回切后质量、Schema、工具选择和延迟是否恢复至批准状态。

“返回了自然语言答案”不是安全降级证据。若无法取得权威结果，高风险场景应按项目规则安全拒绝或转人工。

## 门禁和交接

将运行 NFR 纳入既有状态：

- `PASS`：适用的批准指标与高风险用例全部达标，技术/语义证据可信且基线可比。
- `FAIL`：任一硬 NFR 门禁或高风险有效语义运行失败。
- `REVIEW_REQUIRED`：首版基线、缺少批准阈值、口径/配置不可完全比较或降级语义有争议。
- `BLOCKED`：确定性门禁、环境、数据、脚本或观测使结果不可信。

向发布门禁交付：按组件拆分的当前值/基线/阈值、负载与故障场景、失败样本、降级/恢复结果、线上需监控的 SLI、警戒/停止建议及证据位置。本技能只发信号，不声称已停止或回滚。
