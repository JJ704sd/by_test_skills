# Agent 指标与门禁

本文件以《Agent 非确定性测试流程规范》（2026-05-08）为主。工具规范中的质量数字只作为来源差异记录，不由工具技能升级为产品门禁。

## 指标口径

| 维度 | 默认公式/判定 | 规范默认/批准要求 | policy_class | 主要证据 |
| --- | --- | --- | --- | --- |
| 实体抽取 | 正确字段数 / 总字段数 | Agent 规范 `>=95%` | spec_default | 关键字段精确匹配 |
| 单位归一化 | 归一化后数值与单位符合映射规则 | 项目定义；高风险单位不得出错 | project_required | 规则/转换表 |
| 计算正确性 | 正确结果用例数 / 总用例数 | `100%` | spec_hard_gate | 数值或规则引擎 |
| 指令/约束遵循 | 满足强制字段、指令和禁止项的用例数 / 总用例数 | 项目定义 | project_required | 规则、Schema、人工复核 |
| 推荐合理性 | 符合规则或命中候选范围的用例数 / 总用例数 | `>=90%` | spec_default | 规则 + 人工复核 |
| 输出格式 | 格式正确用例数 / 总用例数 | `>=98%` | spec_default | JSON Schema/规则 |
| 鲁棒性 | 正确处理或给出友好提示的用例数 / 总用例数 | `>=85%` | spec_default | 规则 + 人工判断 |
| 一致性 | 同输入重复运行的关键字段差异率 | `<=5%` | spec_default | 重复采样统计 |
| 幻觉控制 | 幻觉样本数 / 人工抽检总样本数 | `<=1%` | spec_default | 人工复核，LLM 可辅助 |
| 安全性 | 正确拒绝风险输入数 / 风险输入总数 | `100%` | spec_hard_gate | 固定对抗集 + 规则/人工 |

### 跨规范阈值差异

《测试工具选型与使用规范》的 Agent 表对核心实体给出 `>=98%`，而 Agent 专项规范给出 `>=95%`。由于前者位于工具使用语境，不能由工具技能自动覆盖产品质量规范：

- 项目若已正式批准 98% 或更严格值，在 `threshold_profile` 中记录来源、适用对象和批准人后采用。
- 项目未裁定时，按 Agent 专项规范的 95% 做探索性计算，同时输出 `REVIEW_REQUIRED` 并披露来源差异；不得因工具表数字自行判 `PASS`。
- 高风险核心字段仍遵守每次有效运行必须正确的硬规则，不用总体实体率平均掉单次失败。

## 数值与容差

- 核心计算规则正确率必须 100%。优先使用代码/规则引擎计算，模型只解析参数和呈现结果。
- 默认要求精确匹配；存在浮点运算时使用项目批准的**绝对容差**。
- 原规范物流示例的容差是 `±0.01`，不是 `0.01%`。不要把物流示例当作所有业务的通用容差。
- 《测试工具选型与使用规范》另写相对浮点误差 `<=0.01%`，与这里的绝对容差不是同一口径。阈值配置必须注明 `absolute` 或 `relative`；项目未批准口径时，核心计费使用精确匹配，无法精确匹配则置为 `REVIEW_REQUIRED`，不要自行二选一。
- 示例：快递/空运体积重 `CBM × 167`，计费重 `max(实重, 体积重)`；海运规则以正式货代规则为准。

## 采样和统计

- 每条非确定性用例预先声明 3-5 次有效运行；随机性高或结果接近阈值时扩大样本。
- 对 100% 指标，每次有效运行都必须通过；不能用重复成功冲淡一次有效失败。
- 同时报告用例数、计划运行数、有效运行数、技术失败数和语义失败数。
- 对比例指标给出分子、分母和值；样本足够时给出 95% 置信区间（可使用 Wilson 区间）。3-5 次只是每用例的默认下限，不代表单条用例有充分统计把握。
- 一致性必须声明比较单位。默认把首个有效运行作为参考，计算其余有效运行中关键字段超出允许差异的运行数 / 可比较运行数；如项目采用成对比较，显式记录方法并保证基线一致。

## 基线变化

原规范规定“核心指标相对基线恶化超过 10% 触发专项评审”，但未说明百分点或相对百分比。统一按以下方式报告：

- 高值优指标相对退化：`(baseline - candidate) / baseline`。
- 低值优指标相对退化：`(candidate - baseline) / baseline`。
- 同时报告绝对百分点变化；基线为 0 或相对值无定义时只报告绝对变化并触发人工评审。
- `threshold_profile` 已批准计算方式时按其判门禁；未定义时，相对退化 `>10%` 置为 `REVIEW_REQUIRED`，不得自行判通过。

## 准入与准出

准入：

- Agent 相关的确定性 API 连通、服务可用、基础对话和工具子门禁为 `PASS`。整体 `PASS_WITH_ACCEPTED_RISK` 的继续执行是跨技能治理增强，仅在相关子门禁仍为 `PASS` 且全部接受风险明确不影响本评测时允许；不得用它放宽原规范前置要求。
- 测试集已脱敏、版本化并覆盖本次变更。
- 上一版本基线已归档；首版进入 `create_baseline`。
- Prompt、模型、参数、规则、知识库、工具和 Schema 变更已列明。

准出：

- 全部核心指标达到批准阈值。
- 基线无显著退化，或专项评审已形成正式结论。
- 计费、计算、权限、安全和对抗高风险集 100% 通过。
- 人工抽检无严重缺陷，LLM 评审不是唯一依据。
- ND-P0/ND-P1 已修复并回归；通用缺陷严重度 P0/P1 由确定性测试门禁关闭。

规范默认值可用于探索性报告；正式 `PASS` 要求生效阈值清单已批准。高风险判据缺失为 `BLOCKED`，其他阈值未批准为 `REVIEW_REQUIRED`。
