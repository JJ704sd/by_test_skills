# Skills 针对性精简设计规范（v2）

状态：已实施并验证
日期：2026-08-11
范围：`skills/`、`docs/`、`README.md`、`CONTRIBUTING.md`、`scripts/Test-Skills.ps1`

## 1. 背景与基线

上一轮已完成技能去重、重命名、资源分层和元数据规范化，将技能数从 30 个降至 25 个。本轮不再做目录级大迁移，而是针对仍然偏重、重复或耦合运行时编排的内容继续精简。

实施前基线：

| 指标 | 基线 |
| --- | ---: |
| 场景组 / 技能 | 8 / 25 |
| `SKILL.md` 行数 / 字符数 | 1,007 / 54,716 |
| 配套资源文件 | 54 |
| 配套资源行数 / 字符数 | 3,541 / 121,638 |
| 07 质量组 `SKILL.md` 行数 | 269 |
| 07 质量组配套资源行数 / 字符数 | 2,210 / 60,842 |

07 质量组占全部配套资源行数的 62%，是本轮主要优化面。

## 2. 问题陈述

1. 五个质量技能的主入口重复展开职责转交、输出导航和同义门禁说明，增加每次触发后的固定上下文。
2. 多份 NFR reference 重复解释已不随仓库分发的上游文档、`source_layer` 分类和“治理增强”来源；运行时真正需要的是精确来源、批准状态和适用范围。
3. 质量 reference 同时保存完整输入、完整输出、完整报告和跨技能包，字段大量重叠，且把一种传输格式误写成唯一工作流。
4. 工具目录把能力要求与具体产品混在一起；产品、版本、许可和维护状态会变化，静态品牌清单不应替代现场核验。
5. `research`、架构审查和双轴代码审查把子代理编排写成默认动作。并发方式应由当前运行环境和用户授权决定，不属于领域技能的硬约束。
6. `route-engineering-work` 没有覆盖五个质量技能，作为总路由器并不完整。
7. 校验器能检查上限和坏链接，但不能发现未从 `SKILL.md` 直接路由的孤立资源。

## 3. 目标

- 保留 25 个稳定用户意图和现有目录名称。
- 保留五个质量技能各自独立的决策权，不合并为总控技能。
- 让 `SKILL.md` 只承载每次调用都需要的流程、边界和硬规则。
- 让 reference 只承载按分支读取的方法、字段或模板，并删除来源考据与同义重复。
- 用 `source_ref + approval_status + scope` 取代固定的 `source_layer` 枚举。
- 将工具选择改为“能力契约优先，候选产品现场核验”。
- 移除领域技能对特定子代理编排方式的依赖。
- 增加资源直达校验，防止未来出现无法发现或只被深层引用的文件。

量化验收目标：

| 指标 | 目标 |
| --- | ---: |
| 技能数 | 25 |
| `SKILL.md` 总行数 | `<= 900` |
| `SKILL.md` 总字符数 | `<= 50,000` |
| 07 质量组 `SKILL.md` 行数 | `<= 225` |
| 07 质量组配套资源行数 | `<= 1,800` |
| 失效相对链接、孤立资源、旧技能调用 | 0 |
| 强制子代理编排语句 | 0 |

行数是防回弹指标，不是压缩目的；不得通过合并成超长行规避限制。

## 4. 非目标

- 不删除、重命名或新增技能。
- 不改变测试范围、工具治理、测试准出、Agent 评测和生产发布五种决策权的归属。
- 不放宽生产压测、安全扫描、破坏性故障注入、Secret、隐私、审批、回滚或证据要求。
- 不把项目阈值改成仓库默认值，也不根据示例数字生成批准结论。
- 不安装依赖、不访问生产系统、不发布仓库变更。
- 不重写与本轮问题无关的模板资产或领域技能。

## 5. 设计原则

### 5.1 主入口保持最小充分

每个 `SKILL.md` 只保留：

1. 决策权与关键排除；
2. 最短可执行工作流；
3. 不可违反的安全或证据约束；
4. 按工作流节点直达的 reference 链接。

删除独立的 reference 目录复述、重复输出模板说明和已在 description 中表达的触发条件。

### 5.2 来源契约面向证据，不面向历史

需要阈值、规则或事实来源时，统一记录：

- `source_ref`：可核验的项目文档、标准、批准记录或查询；
- `approval_status`：`APPROVED`、`UNAPPROVED` 或 `NOT_APPLICABLE`；
- `scope`：对象、环境、版本和时间窗口。

仓库基线或示例只能辅助设计，不得自动升级为项目门禁。

### 5.3 决策、授权和执行状态分离

精简不能合并以下状态轴：

- 门禁事实结论；
- 当前操作者是否获权；
- 动作是否已请求、执行或验证。

未知证据不能伪装为通过，已知硬失败也不能因操作者无权而降级为“待补证据”。

### 5.4 资源保持一层直达

`references/`、`assets/` 和 `scripts/` 中的每个文件必须由同一技能的 `SKILL.md` 直接链接或点名。reference 之间可以交叉引用，但不能成为发现某个资源的唯一入口。

### 5.5 编排策略由运行环境决定

技能描述任务分解和独立检查，不强制要求子代理。当前环境允许且任务受益时可以并行；不可用时同一流程必须能在当前会话完成。

## 6. 分批实施

### 批次 A：低风险入口与路由

- 补齐 `route-engineering-work` 对五个质量技能的路由，并压缩重复边界说明。
- 从 `research`、`review-codebase-architecture` 和 `review-code-against-spec` 删除默认子代理要求，保留独立调查或双轴检查的语义。
- 压缩 `wizard` 的背景解释，保留模板不可手改、人工确认、静态验证和 Secret 边界。
- 精简五个质量 `SKILL.md`，把 reference 链接放到实际使用步骤。
- 同步简化五个质量技能的 `agents/openai.yaml` 文案。

### 批次 B：质量 reference 去重

- 删除反复出现的上游文档考据和 `source_layer` 枚举，改用来源三元组。
- 删除未获项目批准的伪精确默认值；确需保留的仓库基线必须标明不可直接用于门禁。
- 合并同一 reference 内重复的输入、输出、报告和交接字段，只保留最小契约与必要扩展。
- 将工具目录改为能力矩阵；具体产品只作为经现场核验后写入决策记录的候选。
- 保留门禁状态、严重度、硬失败、灰度、回滚、脱敏和证据可追溯约束。

### 批次 C：校验与文档同步

- 在 `scripts/Test-Skills.ps1` 增加同技能资源必须从 `SKILL.md` 直达的检查。
- 更新 README、贡献指南和技能分布文档中的 v2 原则与指标。
- 运行结构校验、Markdown 链接检查、`git diff --check` 和针对性文本审计。

## 7. 行为不变量

实施后必须继续成立：

- 范围技能定义“测什么”；工具技能定义“如何安全测”；流程技能定义“测试阶段是否准入/准出”；Agent 技能定义非确定性质量信号；发布技能独占生产流量和回滚决策。
- 阈值缺少批准、口径、环境、窗口或证据时，不得输出正式通过。
- P0/P1、高风险有效失败、越权、安全、计费和数据错误不能被平均值抵消。
- 生产环境不得用于压测、安全扫描或破坏性故障注入。
- 诊断、审查和门禁不得虚构已经执行的动作或证据。
- 技能目录可独立复制；不得依赖场景目录根部的共享运行时文件。

## 8. 验证方案

1. 运行 `powershell -ExecutionPolicy Bypass -File scripts/Test-Skills.ps1`。
2. 统计总量和 07 组预算，与本规范基线比较。
3. 搜索 `source_layer`、强制子代理措辞和已退休技能调用。
4. 检查每个资源都从所属 `SKILL.md` 直接路由。
5. 运行 `git diff --check`，审查变更只涉及本规范范围。
6. 对每个质量技能各检查一条应触发和一条应排除请求，确认决策权未漂移。

## 9. 回退原则

若精简导致门禁歧义、资源无法发现或关键安全约束丢失，优先恢复对应段落，不通过放宽校验或合并决策权来“修复”指标。所有删除内容仍可从 Git 历史恢复。

已完成：

- 五个质量决策权和全部生产/证据硬边界保持独立。
